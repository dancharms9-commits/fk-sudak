## Дополнительно: 246 перезагрузок профилей без сети

Одноразовая браузерная проверка выполнена отдельно от существующих тестов:

1. Локальный сервер отдаёт неизменённые файлы репозитория.
2. Приложение получает собственный `data.json`, активирует настоящий SW v11
   и сохраняет набор данных. Внешние портреты блокируются, чтобы исключить
   успешную загрузку из HTTP-кэша.
3. Сеть отключается через `BrowserContext.setOffline(true)`.
4. Все 41 hash-маршрут профиля открываются и **каждый перезагружается** при
   ширинах 320, 390 и 768 px, в светлой и тёмной теме (41 × 3 × 2 = 246).
5. После каждой перезагрузки сверяются имя, ссылка на собственный профиль РФФК,
   все шесть полей статистики с исходным `data.json`, инициалы заглушки,
   отсутствие горизонтального переполнения и сообщение «Нет связи».

**Результат: 246/246 успешно; необработанных ошибок JavaScript 0.**
Это подтверждает работу сохранённых профилей и заглушек при потере сети.
Это не проверка офлайн-доступности самих внешних фотографий: они в SW не кэшируются.

- Для шести выбранных кандидатов: HTTP 200, корректный тип и сигнатура,
  размеры, просмотр настоящего портрета в памяти; ФИО/дата/биография сопоставлены
  с РФФК. Для Симончука сохранено подтверждённое пользователем исключение даты.
- Два существующих фото РФФК обнаружены в собственных карточках 1299 и 806,
  проверены на доступность. Новые файлы/URL в приложение не добавлены;
  перепривязки фото и идентификаторов нет.
- Автоматические проверки существующих карточек сверяют `src` с данными своего
  профиля и отвергают чужой источник; это не биометрическая идентификация лиц.
- Для новых WebP, новой обрезки и нового precache результат **не применимо**:
  разрешённых новых изображений нет, эти действия не выполнялись.
- Гарантированного офлайн-кэша внешних фото нет. При ошибке/отсутствии сети
  проверено отображение инициалов. Фото из отчёта не подключаются к приложению.
- При полном отсутствии ранее сохранённых данных офлайн нельзя получить все
  41 профиль: существующее приложение показывает сообщение о недоступных данных.
  Этот случай также покрыт существующими браузерными тестами.

## Сохранность функций и GitHub

`git diff` относительно базы подтверждает отсутствие изменений в HTML, CSS,
SW, manifest, данных, сборщиках статистики и workflow. После добавления документов
`git diff --cached --check` проходит.

Существующий workflow `.github/workflows/update.yml` запускает проверки PR только
для перечисленных путей приложения/тестов. Изменения только в `docs/` в этот
список не входят, поэтому успешный GitHub Actions для данного PR не заявляется:
перечисленные результаты получены локально. Ветка предназначена для PR в `main`,
без самостоятельного объединения.
