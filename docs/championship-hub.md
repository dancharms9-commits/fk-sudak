# Чемпионат РК, сезон 2026

## Аудит и границы изменения

Рабочая ветка `feat/championship-hub` создана от `origin/main` `31538d6`.
PR #19 уже был объединён (`445af2d`); четыре клубных WebP входят в main
и сохранены. До изменений прошли 29 Python- и 48 Node-тестов.

Приложение остаётся buildless PWA: один `index.html`, встроенные стили,
`fetch_data.py` → `data.json`, дополнительное обогащение профилей через
`update_player_stats.py`, почасовой GitHub Actions и существующий SW.
Пять нижних вкладок и все клубные экраны сохранены. `#table` остаётся
совместимым адресом, но вкладка называется «Чемпионат». Внутри — таблица,
туры/матчи и бомбардиры. Таблица использует прежний `table`, без пересчёта.

## Контракт JSON и ошибки источника

Старые ключи `table`, `res`, `next`, `squad`, `coach`, `news`,
`player_stats_2026`, `match_details` сохранены. Клубный календарь отдельно
от общего и продолжает открывать прежний центр матча.

Добавлен `championship`:

- `season`, `competition_id`, `source_url`;
- `calendar`: `teams`, `rounds`, `matches`, `source_url`, `updated`, `stale`;
- `scorers`: `players`, `coverage`, `source_url`, `updated`, `stale`.

У команды сохранён ID РФФК, ссылка, название или `null`, проверенная ссылка
на эмблему. У матча — ID протокола, если опубликован, а также постоянный
ключ `4:2026:тур:хозяева:гости`. Этот ключ не меняется при переносе даты
и появлении протокола. Повторные карточки убираются; конфликтующие повторы
отклоняют обновление раздела. Неполная пара счёта хранится как `null/null`.
Дата берётся только из поля матча. Технический статус не превращается в дату.
Поля `data-team1`, `data-team2`, `data-end`, `data-id`, `data-col` используются
вместе с семантическими контейнерами полного календаря/рейтинга.

Бомбардиры сохраняют официальный ID, место и исходный порядок, включая
равные голы. Команда определяется точным именем из календаря. Ссылка на
местный профиль требует одновременно ID команды 141, ID игрока и полного
нормализованного имени. Не используется сопоставление по одной фамилии.

Разделы обновляются независимо. Ошибка сети, неверный сезон, неполная
разметка, потеря прежних туров/матчей/части рейтинга оставляют предыдущий
снимок и прежнее время успешного получения; выставляется `stale=true`.
Сбой клубного источника также не блокирует обновление чемпионата.
Атомарная запись JSON сохранена. Прежний проверенный протокол сохраняется
при временной ошибке загрузки только при совпадении ID, даты, команд и счёта.

`fetch_data.py` сохраняет проверенные профильные URL и фотографии даже
у игроков без сезонных показателей. Сохранённые показатели не выдаются
за свежее подтверждение общего рейтинга: `leaderboard_current` отделяет их
от реально полученных значений. `update_player_stats.py` применяет проверку
противоречий только к свежим значениям рейтинга; старые числа не мешают
получить новую статистику профиля.

## Навигация, обновление и офлайн

Выбранный подраздел, тур, обе команды фильтра, статус и поисковый запрос
хранятся в `sudak-championship-v1`. Фильтры не изменяют список доступных туров.
Первый выбор — тур ближайшего будущего матча по московской дате, если
он однозначен; иначе последний опубликованный тур с матчами. На 04.11 — 19-й.
Прежние маршруты, Back, фокус и прокрутка расширены родителем `from=table`,
в том числе для переходов профиль → гол → матч.

Кнопки и поля имеют область нажатия от 44 px; вкладки управляются также
стрелками/Home/End, есть ARIA-метки, обе темы и reduced-motion.
Эмблемы сторонних команд загружаются только по проверенным URL РФФК;
при отсутствии сети/изображения остаётся нейтральное обозначение.

GitHub Actions по-прежнему запускает обновление раз в час (`0 * * * *`).
Открытое приложение проверяет JSON каждые пять минут, при фокусе,
возвращении на вкладку и восстановлении сети. Новый JSON сохраняется
в прежнем `sudak-data-v1`. Тур, фильтры, поиск, раскрытый матч, фокус ввода
и прокрутка сохраняются при перерисовке. Перезагрузка для новых данных не нужна.

SW `sudak-championship-v13` сохраняет прежнюю стратегию: network-first
для оболочки, precache клубных изображений, исключение `data.json` из SW.
JSON для офлайна восстанавливается из localStorage, как прежде.
Стили нового раздела встроены в HTML; нового обязательного сетевого
ресурса для запуска нет. Старые `sudak-*` кэши удаляются при активации.
Manifest и установка PWA не изменены.

## Проверки

Команды CI:

```sh
python -m unittest discover -s tests -v
node --test tests/*.test.cjs
node tests/championship.browser.cjs
```

Также запускаются все прежние семь браузерных сценариев из workflow.
Новый сценарий проверяет три подраздела на 320/390/768/1440 px в обеих
темах, одну строку управления туром, отсутствие переполнения, переключение
туров, фильтры, поиск, точные переходы, Back/фокус/прокрутку, обновление
JSON без reload, реальное обновление SW v12 → v13, офлайн-перезагрузку,
протокол/профиль/рейтинг без сети и восстановление связи.

Фикстура `tests/fixtures/championship-2026.html` — реальный снимок полных
разделов и краткого блока текущего тура без новостей и счётчиков. Тесты
не используют сеть. Снимок старого SW нужен для проверки реальной миграции.
Скриншоты всех новых подразделов загружаются артефактом GitHub Actions.

Локальная среда: ARM64 Termux, существующий headless Chromium и Playwright
из рабочего окружения; для запуска Node используется локальный адаптер
определения платформы. Установленные Android PWA и системный диалог
установки не управляются этими тестами: проверяется реальный Chromium/SW,
manifest и прежние проверки ресурсов, без заявления о физической установке.

Финальный локальный результат: 45 Python- и 59 Node-тестов прошли.
Восемь браузерных сценариев: общий регрессионный, чемпионат, фотографии,
главная, центр матча, переходы вкладок, перезагрузка вкладок и заставка.
Итог каждого браузерного сценария записан в описании PR после завершения.

Дополнительно оба настоящих скрипта почасового обновления выполнены
последовательно в изолированной копии данных: сохранены 41 ID профиля,
16 протоколов, 22 тура, 113 матчей и 25 бомбардиров; дополнительный скрипт
получил свежую статистику 38 игроков. В итоговом PR прежние клубные поля
JSON сохранены побайтно по значениям, добавлен только блок чемпионата
и обновлено общее время снимка.
