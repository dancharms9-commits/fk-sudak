# Индекс регистраций игроков РФФК

Замер сделан на `data.json` с 871 регистрацией. База сравнения — `b9f39b2`,
`main` после слияния PR #45. Инструмент запускает `adoptData()` и `applyRoute()`
из обоих вариантов `index.html`, считает перечисления всех ключей объекта
регистраций и сравнивает HTML целевой секции посимвольно.

| Страница | Первый заход на снимке, до → после | Повторный заход, до → после |
| --- | ---: | ---: |
| Состав СК «Каштан» (`936`) | 174 → 1 | 174 → 0 |
| Состав ФК «Саки» (`146`) | 204 → 1 | 204 → 0 |
| Профиль Никиты Попова в «Каштане» (`146:936`) | 14 → 1 | 14 → 0 |
| Профиль Сергея Барканова в УОР (`1698:117`) | 14 → 1 | 14 → 0 |
| Профиль Сергея Барканова без клуба (`1698`) | 12 → 1 | 12 → 0 |
| Центр матча `rffk-38771` | 37 → 1 | 37 → 0 |

В каждой строке первый заход измерен на отдельном снимке. Приём данных сам по
себе делает 0 обходов в обеих версиях. Один обход при первом обращении строит
общий для маршрутов индекс. HTML совпал на всех шести маршрутах.

```sh
baseline=$(mktemp)
git show b9f39b2:index.html > "$baseline"
RFFK_BASE_HTML="$baseline" node tests/rffk-membership-harness.cjs
```

Индекс хранит упорядоченный список регистраций игрока и списки по каждому
клубу. Записи сотрудников остаются в полном списке профиля и исключаются из
клубного поиска. Ключ `WeakMap` — сам принятый объект `PLATFORM`. Когда сеть
или localStorage передаёт новый принятый объект, следующий поиск строит индекс
для него. Устаревший ответ, отклонённый проверкой ревизии, сохраняет текущий
снимок и его индекс. Списки ссылаются на записи снимка, поэтому добавочные
затраты памяти линейны по числу регистраций. По-прежнему выполняются проверки
списков состава, записей конкретного игрока и протоколов. Время отрисовки
в миллисекундах не измерялось.

## Проверки

Локально прошли все 217 тестов `python -m unittest discover -s tests -v`,
все 177 тестов `node --test tests/*.test.cjs` и `git diff --check`.

Набор Node включает сравнение с прежним селектором для
опубликованных пар «игрок — клуб», отдельные проверки истории, сезонных и
клубных записей, фотографий, сотрудников, отсутствующих дат и регистраций,
замены сетевого и сохранённого снимков и счётчиков обходов. Тест предупреждений
КФС воспроизводит время своего снимка, чтобы устаревание фикстуры не влияло на
проверку исчезновения ошибки синхронизации.

GitHub Actions запускает Chromium для составов и
профилей, в том числе смену клуба игрока и обновление списка регистраций без
перезагрузки, а также тесты реального offline. Результаты браузерных проверок
и сравнения оформления доступны в [Checks PR #46](https://github.com/dancharms9-commits/fk-sudak/pull/46/checks).
