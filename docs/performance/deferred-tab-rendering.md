# Отложенная отрисовка вкладок

База для сравнения — `main` на коммите `eeb3bc234ec5728ec567e5d93f1fad541b60cc4d` (объединение PR #47). При старте `render()` строила пять основных секций. Затем `applyRoute(true)` выбирала экран. При прямой ссылке на футболиста обе функции записывали содержимое одного и того же профиля.

Теперь `applyRoute()` подготавливает содержимое нужной секции в той же задаче JS, в которой переключает экран. `sudak:ready` отправляется после установки активной секции и восстановления состояния маршрута. Без hash строится Главная. При прямом открытии вкладки, профиля, клуба или центра матча строится один экран. Если сохранённого снимка нет, сначала видна прежняя резервная разметка этого экрана. Принятый сетевой ответ обновляет её на месте.

## Актуальность секций

- `renderedTabs` хранит основные вкладки с подготовленным содержимым. Отсутствие вкладки в наборе означает, что она ещё не строилась или устарела. Остальная разметка остаётся в DOM между переходами, поэтому сохраняются узлы, раскрытые элементы и состояние управления.
- Принятая версия `data.json` помечает Главную, Матчи, Состав, Новости и представление РФФК Чемпионата. Активный экран обновляется сразу. Скрытая вкладка обновляется перед следующим показом. Смена амплуа влияет на Состав и ссылки на игроков с Главной. На Главной также учитывается смена московского дня.
- Выбор турнира меняет содержимое общей секции Чемпионата. Тур, фильтры и поиск остаются в существующих состояниях РФФК и КФС. Изменение футбольных данных КФС обновляет его активное представление или помечает скрытое. Обновления отметок проверки и предупреждений в КФС применяются к отдельным узлам, в том числе при возврате на вкладку. Отдельный снимок протоколов также обновляет календарь КФС, если тот уже выбран.
- Сетевые проверки РФФК и КФС идут по прежним путям независимо от экрана. Приём и восстановление сохранённых снимков, защита от устаревших ответов, загрузка составов, история браузера и Service Worker используют существующие механизмы. Кэш индекса регистраций РФФК и единая запись готового профиля остаются в своих обработчиках.

## Замер

Из корня репозитория сохраните базовый HTML и запустите сравнение на текущем снимке.

```sh
git show eeb3bc234ec5728ec567e5d93f1fad541b60cc4d:index.html > "${TMPDIR:-/tmp}/sudak-base.html"
PERF_BASE_HTML="${TMPDIR:-/tmp}/sudak-base.html" node tests/deferred-tab-rendering-benchmark.cjs
```

Скрипт исполняет код из обоих `index.html` в Node VM с одинаковыми футбольными снимками и фиксированным временем. Счётчик перехватывает присваивания `innerHTML` корням основных и детальных секций и трём блокам Главной. Он учитывает число затронутых секций, даже если в одну секцию пишут дважды. Отметки, поиск и прочие частичные записи вне этих блоков в счётчик не входят. Фаза запуска заканчивается в момент `sudak:ready`, перед обработкой ответов сети.

| Сценарий | Секции | Записи в корни | Записи блоков Главной | Всего записей |
| --- | ---: | ---: | ---: | ---: |
| Запуск без hash, с резервными или сохранёнными данными | 5 → 1 | 4 → 0 | 3 → 3 | 7 → 3 |
| Первый обход пяти вкладок после запуска с сохранённым снимком | 0 → 4 | 0 → 4 | 0 → 0 | 0 → 4 |
| Повторный обход без изменений | 0 → 0 | 0 → 0 | 0 → 0 | 0 → 0 |
| Новый счёт РФФК при открытой Главной | 5 → 1 | 4 → 0 | 1 → 1 | 5 → 1 |
| Открытие Матчей после этого обновления | 0 → 1 | 0 → 1 | 0 → 0 | 0 → 1 |
| Устаревший сетевой ответ РФФК при открытых Матчах | 0 → 0 | 0 → 0 | 0 → 0 | 0 → 0 |
| Прямая ссылка на футболиста, без снимка или с сохранённым снимком | 6 → 1 | 6 → 1 | 3 → 0 | 9 → 1 |
| Прямая ссылка на клуб или матч, без снимка или с сохранённым снимком | 6 → 1 | 5 → 1 | 3 → 0 | 8 → 1 |

Разметка каждой из пяти открытых вкладок, таблиц обоих турниров, трёх детальных страниц и Матчей после обновления совпала с базовой побайтно при фиксированном времени.

В Termux на ARM64 с Node v24.22.3 медиана холодного синхронного этапа от `restoreSavedData()` до `sudak:ready` составила **3,14 → 1,55 мс**. Для каждой версии использовались пять прогревочных и 20 измеряемых запусков с чередованием порядка версий. Это замер JS в тестовой VM. Он исключает DOM браузера, загрузку, стили, компоновку и заставку. Время до первого кадра PWA и поведение на физических устройствах по нему не оцениваются.

Существующие сценарии проверяют историю, прокрутку, фокус, анимации, фотографии, герб, заставку и работу установленного Service Worker офлайн.
