# Одна запись в DOM профиля футболиста

В `renderPlayer()` профиль игрока ФК «Судак» сначала записывал основную разметку в `#player`, затем дописывал список подтверждённых матчей через `innerHTML +=`. Браузер сериализовал уже созданные узлы, разбирал объединённую строку и заново создавал всё содержимое секции.

Теперь `renderPlayer()` собирает основную разметку и один раз вызывает `playerMatchesHTML(p)`. Обе строки записываются вместе. После записи обработчик ошибки фотографии по-прежнему удаляет изображение, оставляя инициалы.

## Замер в Chromium

Тест перехватывает сеттер `innerHTML` на `#player` на время одного вызова `applyRoute()`. На обеих версиях используются одни и те же футбольные данные. Базовая версия — `main` на коммите `e237930` после PR #46.

| Маршруты | Записей до | Записей после |
| --- | ---: | ---: |
| Илья Донской, Владимир Семенов с главной, Илья Донской с клубным контекстом «Судака» | 2 | 1 |
| Никита Попов в «Каштане», Сергей Барканов без клубного контекста, Валентин Манякин в «Таврии» КФС, неизвестный игрок | 1 | 1 |

Сериализованное содержимое `#player` совпало на всех семи маршрутах, включая порядок блоков, атрибуты и ссылки. Замер считает полные записи на один рендер. Время загрузки и отрисовки в миллисекундах не измерялось.

```bash
git show e237930:index.html > /tmp/fk-sudak-player-base.html
MULTI_CLUB_BASELINE_HTML=/tmp/fk-sudak-player-base.html node tests/roster-profiles.browser.cjs
```
