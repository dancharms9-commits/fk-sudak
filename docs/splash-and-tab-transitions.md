# Заставка и переключение вкладок

Основа: `origin/main` a5bcb4d, включающий объединённый PR #16 (merge 0c02a65).

## Заставка

Прежний контроллер запускался при каждом новом документе HTML без проверки типа
навигации. Поэтому и браузерная перезагрузка, и Android pull-to-refresh повторяли
всю заставку.

Теперь короткий синхронный скрипт в head читает
`performance.getEntriesByType('navigation')[0].type` до первого кадра:

- `navigate`: показать настоящую заставку; прежний интервал 3500 мс начинается
  после готовности интерфейса и загрузки утверждённой PNG-эмблемы;
- `reload` и `back_forward`: сразу убрать фон запуска, удалить скрытый overlay
  до разблокировки HTML, не запускать таймер и не назначать inert интерфейсу;
- старый Navigation Timing: эквивалентные типы 0/1/2;
- неизвестный тип или отсутствие API: предсказуемо пропустить заставку.

Источник семантики типов: [Navigation Timing](https://www.w3.org/TR/navigation-timing-2/#dom-navigationtimingtype).

Контроллер существует один раз в документе. Hash-маршруты, обновление данных,
focus/visibility, переходы матч ↔ футболист не создают новый overlay. `pagehide`
завершает ещё активную заставку перед уходом: восстановление BFCache не продолжает
её с середины. Прежние обработчики ошибок и watchdog 8 с сохранены. Изображение,
длительность, доступность reduced motion и системная заставка WebAPK не меняются.
`sessionStorage`, `localStorage`, TTL, unload и таймеры определения «закрытия»
не используются.

**Граница надёжности:** веб-страница видит навигацию документа, а не завершение
Android-приложения. Новый документ с типом `navigate` показывает заставку даже
при наличии старого sessionStorage. Сохранённый документ или запуск,
классифицированный браузером как `reload`/`back_forward`, пропускает её даже после
полного закрытия задачи. Это сознательный выбор в пользу отсутствия повторов.
Прямой переход по ссылке в новый документ тоже является `navigate`.

## Переходы

В существующий `applyRoute` добавлена подготовка и запуск Web Animations API.
Маршрут, активная кнопка, показ нового раздела, фокус и прокрутка меняются
синхронно в прежнем порядке. Анимация — 200 мс, `cubic-bezier(.2,.65,.3,1)`,
opacity 1 → 0 / 0 → 1 и translateY 0 → −6 px / 6 → 0.

Анимируются только пять основных разделов. Исходный раздел на время Fade выходит
из потока в фиксированный слой с прежними координатами и шириной. Clip-path
ограничивает его областью содержимого над меню; слой inert, aria-hidden и не
перехватывает нажатия. Высоту документа сразу определяет новый раздел. DOM не
копируется и не пересоздаётся ради анимации; фильтры, раскрытые блоки и ссылки
остаются прежними. Нижнее меню не входит в анимацию.

Каждая следующая навигация сначала отменяет обе предыдущие анимации и очищает
временные свойства, inert и aria-hidden. Есть только один текущий переход;
старые Promise callbacks не могут отменить новый. Уход в профиль/матч и pagehide
тоже очищают переход. При reduced motion переключение мгновенное; включение
настройки посреди перехода сразу завершает его. При отсутствии WAAPI остаётся
обычная синхронная навигация. Зависимости не добавлены.

## PWA и данные

SW получает имя кэша `sudak-tabs-v10`. Список офлайн-ресурсов и механизм обновления
не меняются: install перечитывает оболочку, skipWaiting/claim активируют новую
версию, activate удаляет прежние sudak-кэши. Не добавлено принудительных reload.
Почасовое расписание, опрос данных и SW update сохраняются. Visual updater
принимает v10 и остаётся идемпотентным. Данные, статистика, эмблемы, иконки и
маршруты не изменены.

## Проверки

- Python: `python -m unittest discover -s tests -v` — 29 тестов.
- Node: `node --test tests/*.test.cjs` — 47 тестов, включая новую политику запуска,
  недоступное хранилище, приоритет Navigation Timing 2, legacy и неизвестный API.
- Браузер: все существующие browser, home-dashboard, match-center, launch-splash
  плюс новый tab-transitions; настоящий Chromium в Termux.
- 320/390/768/1440 px × light/dark × motion/reduce; кадры перехода проверяют
  фиксированные координаты меню, постоянную высоту, отсутствие горизонтального
  переполнения и пустых кадров. Снимки переходов сохраняются в CI-артефакт.
- Все 20 направлений между вкладками, 75 быстрых переключений (без пауз, 16 и
  80 мс), отмена при reduced motion, Back во время перехода, фильтр состава,
  прокрутка/фокус, профиль/матч, раскрытые запасные, Forward и прямая ссылка.
- Реальная смена SW v9 → v10: исходный кэш содержит отличимую старую HTML-заглушку;
  новый кэш содержит политику заставки и контроллер переходов. Затем сеть
  отключается в Chromium: offline reload без заставки, все вкладки, сохранённые
  события и составы; возврат сети без повторной заставки. Старые наборы также
  проверяют обновление v6/v7/v8, все 41 профиль и работу без сохранённых данных.
- Перезагрузка проверяется через browser reload и `location.reload()` на каждой
  вкладке; также проверяются новая навигация с прежним sessionStorage и возврат
  по истории, в том числе уход во время заставки.

Нативный жест Android pull-to-refresh, установка/полное закрытие WebAPK и системная
заставка ОС не проверены физически: headless Chromium проверяет веб-путь reload и
жизненный цикл документа. Производительность на слабом физическом Android
не измерялась. Браузерные тесты не дают гарантии поведения диспетчера задач Android.
