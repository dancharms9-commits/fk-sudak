## Представление и связи

Один `#team=<teamId>` и один `renderClub` в `index.html`. `clubContext` выбирает данные `platform v1`, строго сезон `4:22` (2026), по строковым ID. Подтверждённый реестр: Судак `141`, Каштан `936`, СТО-Газель `1030`, Фуна `932`, АФК `521`, НКСТРОЙ-Керчь `930`, Саки `146`, Сталкер `934`, Турбо `757`, Темп `1028`, УОР `117`. Неизвестные `0`, `258`, `1029` не получают ссылок и клубных данных.

- `#team=141` отображает существующую главную «Судака». Пустой hash и `#home` сохраняют прежнее поведение.
- Остальные 10 команд используют общий экран: название, город, официальная эмблема, место/очки/игры, победы/ничьи/поражения, забитые/пропущенные/разница, до пяти последних результатов, все загруженные подтверждённые будущие матчи, состав и статистика при наличии, ссылка РФФК и список 11 клубов.
- Таблица теперь читает полную `platform.standings['4:22']`, связывает названия и эмблемы по teamId. Старый TABLE не сопоставляется по тексту. При старом JSON без platform отображается прежняя таблица без вымышленных ссылок. Главная продолжает читать прежние корневые поля.
- В календаре название/эмблема открывают клуб, раскрытие карточки и ссылка протокола сохраняются. У матча с внутренним центром ссылки клубов выделены поверх общей зоны перехода к центру: нажатие на счёт/остальную карточку сохраняет прежний переход; вложенных ссылок нет.
- Центр существующего матча связывает обе команды через `legacyLinks.matches → matchesById`, без поиска по названию. Старые карточки главной и раздела «Матчи» продолжают открывать центр матча целиком; ссылки клубов доступны внутри центра для подтверждённой ID-связи.
- История использует существующий hash-router и `pushState`, `popstate`/`hashchange`. Кнопка «Назад» возвращает на предыдущую запись, сохраняя раздел, фильтры, позицию и фокус. Для прямого открытия без внутренней записи — переход к чемпионату. На прежней главной `141` остаются браузерный Back и прежняя навигация.

## Данные и честное отсутствие

`data.json` не изменён: **653 847 байт**. Используются 11 строк таблицы и сохранённые 100 матчей с двумя подтверждёнными участниками; экран каждого клуба выбирает свои записи. У «Каштана» полная таблица содержит 17 игр и 51 очко. Прежний снимок TABLE содержит 16/48: он не перезаписывается и не определяет новые клубные показатели.

Полных составов и индивидуальной статистики остальных 10 клубов в platform пока нет. UI сообщает, что загрузка раздела в приложение ещё не выполнена. Это не утверждение об отсутствии информации у РФФК. Общий частичный рейтинг бомбардиров не используется как состав или клубная статистика. Новости не создаются.

При существующих roster/playerSeasonStats renderer использует playerId, teamId, competitionId, seasonId; профиль открывается по проверенному официальному URL. Значения null показываются как «—», настоящий опубликованный 0 сохраняется. Неполнота, давность, время последнего подтверждения, отсутствие публикации и временный сбой различаются. Старый повреждённый/неизвестный optional platform не ломает legacy-корень; уже принятый корректный блок сохраняется.

Будущие матчи: только `scheduled`, две подтверждённые команды, дата текущего сезона не раньше сегодняшнего дня в Москве, неизвестные итоговые счёты. Перенесённые, отменённые, прошедшие без результата и неразрешённые участники не объявляются предстоящими играми. Полные итоги команды берутся из таблицы, а не суммируются из неполного календаря.

## Дизайн, ресурсы и PWA

Новые стили ограничены клубным экраном и новыми ссылками. На нём шапка чемпионата вместо фирменной шапки «Судака»; прежний переключатель темы работает в обеих темах. Крепость, фирменный заголовок и эмблема главной, пять кнопок нижней навигации, профили, иконки и manifest не изменены.

`assets/clubs/<id>.png` — точные копии medium PNG, найденных на официальных страницах соответствующих команд, с тем же именем файла, что у small URL реестра. Это устраняет размытость маленьких 24px эмблем. Источники, размеры и SHA-256: `assets/clubs/sources.json`. Общий объём 10 эмблем — **491 830 байт**, загружаются лениво. При сбое остаются нейтральные инициалы.

Код/стили встроены в существующий HTML, дополнительные обязательные JS-запросы отсутствуют. Индивидуальные профили при запуске не загружаются. `sw.js`, его стратегия/версия, `manifest.json`, production-workflow и настройки Pages не изменены. Существующий SW сохраняет открытый HTML и локальные эмблемы; JSON восстанавливается из прежнего localStorage. Офлайн-перезагрузка посещённой страницы клуба проверяется с настоящим SW. Для ещё не загруженной эмблемы допустим fallback.

Замеры `screenshots/mobile-load.json` — реальный нативный Chromium в ARM64 Termux, мобильный viewport 390×844, локальный HTTP-сервер без ограничения канала/CPU; это не замер скорости production или Android WebView. Сценарий передаёт исходные 653 847 байт JSON из Git без сжатия. Системная установка PWA и системная кнопка Android Back отдельно не автоматизировались.
