## Один экран и прежние маршруты

`matchCenter` принимает старые текстовые ключи «Судака» и общие ключи платформы. Два адаптера данных используют один `renderMatch` и прежние стили центра: заголовок, счёт, составы и хронология. Каноническая ссылка опубликованного матча — `#match=rffk-<officialId>`; до публикации официального ID используется подтверждённый ключ календаря `4:2026:<round>:<homeId>:<awayId>`. Он не выдаётся за ID РФФК. Обе формы остаются доступными после появления протокола.

Клубы и календарь чемпионата открывают матч внутри PWA. Домашняя/гостевая команда ведёт на общий клубный экран; `141` по-прежнему открывает главную «Судака». В составах матча используются `/players/<id>/` из самого протокола. Если сезонная клубная регистрация ещё не подтверждена, открывается общая личность с неизвестными показателями, без придуманной регистрации. Из профиля доступен список матчей, где тот же официальный ID содержится в составе конкретной игры. Список не используется для вычисления сезонных итогов.

Хронология РФФК публикует сокращённые имена текстом, без ссылок на игроков. Эти подписи не превращаются в ID по фамилии или инициалам; такие события не создают персональную статистику. Автогол относится к зачтённой стороне счёта; клуб автора не выводится из этой стороны. Выходы/уходы при заменах сохраняются отдельными событиями, без вымышленных пар.

Статус берётся из календаря: `finished`, `technical`, `scheduled`, `postponed`, `cancelled`, `suspended`. Отсутствие протокола не меняет статус. Дата в прошлом без результата не доказывает, что матч состоялся или был отменён. Для незавершённых матчей случайно сохранённые составы/события не показываются. Город показывается только при явно опубликованном населённом пункте в месте проведения; город клуба не подставляется.

Сохраняются все старые hash-маршруты, 16 прежних протоколов, фотографии, 41 профиль и прежняя статистика. При переходах работают браузерная история, возврат, восстановление прокрутки/фокуса и обновление прямой ссылки. Нижняя навигация содержит прежние пять вкладок. Главная, эмблема, PWA-иконки, CSS главной и фотографии не заменялись.

## Источники и качество

Источники: [официальный календарь сезона 22](https://rffk-roo.ru/tournaments/4/seasons/22/), точные `/matches/<id>/`. Закреплённая страница сейчас перенаправляет на `/tournaments/4/`: допускается только этот официальный адрес, затем проверяются сезон 2026/2026 и контекст турнира. Протокол принимается только при совпадении команд, тура, даты и счёта с календарным ID; ответ с другим URL отклоняется. Профильные страницы при этом не загружаются.

[Первый аудит](https://github.com/dancharms9-commits/fk-sudak/actions/runs/42822517595): 81 запрос в GitHub Actions (один календарь и 80 известных URL матчей), 79 принятых протоколов. [Сводка](match-audit-initial.json) фиксирует отличия от прежнего календаря. Массового сбора на телефоне не было. Дополнительный проход обрабатывает только новые/неуспешные URL; ранее проверенные протоколы берутся из JSON-кеша.

Два работника, тайм-аут до 8 секунд, один повтор только для временных ошибок, ограничение числа матчей и общего времени. Обычная сборка обновляет до восьми протоколов с отдельным бюджетом 90 секунд; TTL успешной проверки — 168 часов. Очередь начинается с давно не проверенных попыток, чтобы одна повреждённая страница не блокировала остальные. Неполученные поля не становятся нулями.

Отдельное `match.protocolQuality` описывает попытку чтения протокола; `match.quality` относится к календарю. `protocol.quality` содержит полноту и времена подтверждения, `eventsComplete` — охват хронологии, необязательное `goalsComplete` — проверку голов по итоговому счёту. При усечённой сводке голов остаются независимые карточки и составы. При повреждении одной команды можно принять другую сторону. Уже подтверждённые разделы, события и `lastVerifiedAt` при отказе сохраняются; меняется только состояние последней попытки. Ошибка структуры/сети — `temporarily_unavailable`, а не утверждение «протокол не опубликован».

Календарь платформы проверяется независимо от старого корня. Его свежая ревизия и протоколы сохраняются при последующем проектировании/восстановлении более старого корня. Сокращённый календарь отклоняется. Если официальный календарь противоречит уже принятому протоколу, запись сохраняется как спорная до проверки; протокол автоматически не удаляется. Старый подтверждённый ID не исчезает лишь потому, что ссылка больше не опубликована в календаре.

## Объём и офлайн

Измерения до/после и мобильные кадры: [match-screenshots](match-screenshots/). HTTP — локальный loopback без ограничения скорости; память — JS heap после GC, не память процесса Android. Замер открытия включает построение экрана и следующий `requestAnimationFrame`. Это проверка локальной работы, не прогноз скорости мобильной сети.

Фотографии не встроены в JSON; используются прежние локальные файлы/официальные URL. Полный снимок сохраняется прежним механизмом localStorage. Реальная офлайн-перезагрузка через существующий SW проверяет протоколы, составы, счёт и переход к игроку. В SW v14 добавлено предварительное кеширование десяти уже имеющихся эмблем РФФК (около 0,5 MB): они доступны даже для ещё не открывавшегося клуба. Прежняя стратегия shell/data и фотографии сохранены; manifest не менялся.

Рост файла за счёт протоколов заметен. Текущий снимок остаётся ниже лимита 5 MB, но следующий безопасный шаг при дальнейшем росте — индекс матчей и manifest ревизии в основном JSON, файлы протоколов по турам/сезону с длиной и SHA-256. Клиент должен сначала загрузить и проверить полный комплект новой ревизии во временный кеш, затем атомарно переключить указатель; до этого хранить прежний полный офлайн-снимок. Запрещено удалять протоколы из нынешнего JSON раньше такой миграции и офлайн-проверок. В этом PR разделение не вводится.
