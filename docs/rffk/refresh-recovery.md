# Восстановление автоматического обновления РФФК

Проверка: 13 ноября 2026 года, Android Termux. База — `main` после PR #44 (`5b5ee09`); рабочее дерево было чистым, выполнен `git pull --ff-only`. Открытых PR с исправлением не найдено.

## Точная причина

В исходном `scripts/build_pages.py`, функция `validate()`, строка 148 на `5b5ee09`, проверка `identities(previous["championship"][section][key], "id") <= identities(hub[section][key], "id")` применялась одновременно к истории календаря и опубликованному рейтингу бомбардиров. Для рейтинга это неверный контракт: `coverage: published_list` не означает полный исторический реестр игроков.

Свежая официальная страница содержит 25 бомбардиров. Из прежних 25 выбыл Донской Илья, ID `202`, 5 голов; появился Шевчук Антон, ID `1202`, также 5 голов. Нижняя граница списка — 5 голов. Парсер календаря и рейтинга успешно получал данные, но `validate(candidate, accepted)` выбрасывал **`InvalidData: Lost championship players`**. Вся новая версия `fetch_data.py` отклонялась, включая результат 1:4. Последующий `update_player_stats.py` мог повысить общий `updated`, сохранив календарь от 7 ноября. Поэтому зелёная публикация и свежая общая ревизия скрывали устаревший раздел.

Это воспроизведено до исправления настоящим `fetch_data.py` в отдельном временном каталоге, на опубликованном JSON. Проверка самого нового JSON без предыдущего снимка проходила; сравнительная проверка падала именно на указанном правиле. Отдельная проекция `platform` проходила. Из [запуска 43467288196](https://github.com/dancharms9-commits/fk-sudak/actions/runs/43467288196) прочитаны журнал и настоящий `football-state-43467288196-1`; checkpoint подтверждает ту же старую версию календаря. Конфликт клубов или протоколов не был причиной этого отказа.

## Исправление

- Рейтинг проверяется отдельно: сохраняются проверки уникальных ID, порядка, мест и количества строк. Выбывание прежнего игрока допускается только для двух `published_list` и если его прежние голы не выше новой нижней границы. Исчезновение игрока выше границы или сокращение ответа отклоняется; сохраняется last-good рейтинг с `stale: true`, календарь проверяется независимо. Профили, составы и индивидуальная статистика не удаляются из-за выбывания из рейтинга.
- Календарь проверяет сохранность конкретных туров, команд, матчей, официальных ID и подтверждённых результатов. Неполный счёт, изменение исторического результата и подмена ID отклоняются. Исправления уже подтверждённых результатов, противоречащие сохранённому снимку, требуют отдельной проверки источника.
- РФФК перестал выводить URL технического матча `38770` в полном календаре, когда текущий тур сменился. Прежде подтверждённые URL сохраняются по неизменному ключу «соревнование / сезон / тур / официальные ID команд», в том числе при восстановлении старых снимков. Существующий другой ID не перезаписывается; проверка истории выполняется после восстановления ссылок.
- До принятия нового снимка календарь проецируется в `platform`, затем проверяется вместе с сохранёнными протоколами. Противоречивые протоколы не удаляются ради принятия обновления. Дополнительная проверка истории `platform` блокирует откат результата даже в checkpoint без протокола этого матча.
- Таблица берётся только из полной официальной таблицы сезона, с проверкой 11 участников и арифметики. При её недоступности прежние строки и дата подтверждения сохраняются, раздел помечается устаревшим, а проверенное обновление календаря принимается. Пересчёта таблицы из нового счёта нет.
- Предупреждения Pages теперь содержат текст причины, раздел, ключ/ID записи и сохранённую ревизию. Итоговый журнал перечисляет изменённые и сохранённые блоки, изменившиеся матчи со счётом/статусом/официальным ID и отдельные предупреждения об устаревших разделах. Ошибка источника продолжает сохранять last-good данные.
